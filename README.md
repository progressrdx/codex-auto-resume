# Codex App Auto Resume · macOS 实验版

为一个明确选定的 **Codex 桌面 App 本地任务**等待额度恢复，并在原任务里启动下一轮。不创建 CLI 替代会话，不切换账号，不购买额度或使用重置券。

这是独立小工具，使用 `light-dev` 的方式开发，不依赖 Project Compass。支持终端命令和适配电脑、手机浏览器的 Web 控制台；被续跑的任务仍留在 App 里。新增原生微信小程序源码（[接入与验收说明](miniprogram/README.md)），尚未完成真机验收。没有原生 iOS/Android App、安装器或开机自启。

2026-08-29：用户 AppID 已接入，微信模拟器实际请求已验证模拟任务开启/停止及真实对话、额度、托管数据一致性；[分层验证记录](VALIDATION.md)。手机可信 HTTPS 和扫码真机仍待完成，不能将模拟器测试视为最终交付。

## 当前验证边界

- 支持本机 App `26.820.60940 / build 7119`，Bundle ID `com.openai.codex`。当前默认路径为 `/Applications/ChatGPT.app`。
- 已实测：App 内部 IPC 连接、具体会话状态读取、账户五小时/周额度及重置时间查询、对正常结束任务拒绝续跑。
- 已通过离线回归：额度等待、周额度优先、状态变化停机、发送结果不确定时禁止重发、防重复进程、审批边界等。见 [验证记录](VALIDATION.md)。
- 已实测：经明确授权，用工具的 IPC 发送接口在同一个测试任务中完成第二轮固定回复，无工具调用；模型、推理强度、工作目录及有效权限保持。此项是单次发送验证，不代表自动控制器的全链路验证。
- **尚未实测：真实额度耗尽后跨自然重置窗口的端到端自动续跑。当前是待试用的实验实现，不能视为已验证可无人值守运行。**

App 内部接口会随版本变化。本工具遇到非已验证版本会停止，而不是猜测协议继续操作。App Server 的公开读取接口文档见 [官方说明](https://learn.chatgpt.com/docs/app-server)。

## Web 与手机浏览器控制台

在本仓库目录运行：

```sh
python3 -m codex_resume web
```

打开终端显示的 `http://127.0.0.1:8765/`，输入该次启动生成的连接凭据。服务默认只监听本机，不需要 npm 或第三方 Python 依赖；这是同一个工具的管理界面，不是另一个 Codex 执行器。

- 查看五小时与每周剩余额度、重置倒计时。额度查询缓存最多 45 秒；倒计时结束不代表账户已经恢复，后台仍会重新查询。
- 分页读取所有可用本地对话（含不同来源与归档），搜索或粘贴 UUID，选中后识别状态。只有执行中或因额度暂停的任务可以加入托管；空对话、本轮已结束、手动停止、归档、等待输入/审批等不会被自动续跑。网页与 CLI 默认累计最多续跑 **3 次**，可调整为 1～100 次。
- 查看监控状态、原因、累计次数和更新时间。页面可见时每 15 秒更新监控记录；额度约每 60 秒刷新。读取失败会标明数据过期。
- 停止监控需确认，不会撤回消息或停止 App 里的工作。正在处理开启请求时，同一服务的停止请求会等开启请求结束后执行，避免先停止后又被开启。
- 关闭或断开网页、停止 Web 服务均不会自动停止已启动的 watcher；需要先在页面或 CLI 中停止对应任务。

### 手机连接

本节说明响应式 Web 手机界面；原生微信小程序请见 [小程序说明](miniprogram/README.md)。没有原生 iOS/Android 安装包。**手机无法通过它自己的 `127.0.0.1` 访问 Mac。** 跨设备访问需要同一可信网络、Mac 的明确 IPv4 地址，以及手机浏览器信任且包含该 IP 的 HTTPS 证书。先自行准备证书和私钥，再运行（下面地址和路径仅为示例）：

```sh
python3 -m codex_resume web --host 192.168.1.50 --port 8765 \
  --certfile /path/to/cert.pem --keyfile /path/to/key.pem
```

手机打开终端给出的 HTTPS 地址，输入连接凭据。浏览器支持时可以“添加到主屏幕”，但没有离线控制或手机后台执行能力。Mac 上的 App、Web 服务和监控进程仍需运行。

本工具不会安装根证书、修改防火墙、创建公网隧道或开启路由器端口映射。拒绝明文跨设备控制以及 `0.0.0.0` 通配监听；地址必须与启动输出一致（包括端口）。目前 HTTPS 已在本机验证，**真实手机与证书信任流程尚未实测**。

### 访问保护

每次 Web 服务启动生成新的随机凭据；所有任务与额度 API 都要求凭据，且拒绝跨站 Origin / Host。凭据仅保存在当前浏览器标签页的 sessionStorage，重启服务后失效。不要将凭据发送给其他人；同一凭据拥有查看任务和管理监控的权限，首版没有多用户权限或独立撤销某台设备的能力。

页面不加载外部脚本、字体或分析服务，不缓存会话数据到离线资源。服务只暴露固定的查询、开启和停止操作，不提供任意命令、续跑提示词、审批或账户修改接口。请只在可信设备及网络内试用，不应当作经过安全审计的公网服务。不要同时运行多个 Web 服务或从 CLI 并发操作同一个任务。

## 准备与只读检查

需要 macOS、Python 3.9+、已登录的 Codex App。没有第三方 Python 依赖。保持 App 运行。无需先手动打开任务页面即可读取所选对话的历史状态。

在本仓库目录执行：

```sh
python3 -m codex_resume doctor
python3 -m codex_resume list
python3 -m codex_resume check 你的任务UUID
```

`doctor` 读取真实额度，不运行模型。`list` 跟随分页游标读取所有可用的本地持久对话，并标明归档；不扫描云端 ChatGPT 对话。`check` 优先读取 App 实时状态，连接不可用时读取明确选中的对话历史。结果区分 `taskState`、`source`、`connection` 与 `canMonitor`；历史资格判断不授权发送消息。任务 UUID 不能用标题或“最近任务”代替。

看到“本轮已结束”时不会额外发送继续；若 App 明确标记长任务目标仍为 active，则在轮次间保留托管。发送仍只处理有结构化 `UsageLimitExceeded` 证据的失败。

App 偶尔会保留已取消的文件夹选择请求。工具仅在同一段连续历史中确认它属于**较早且明确已中断**的轮次时，排除 `codex_app.setup_codex_context_picker` 这一种残留；不会回应或删除它。当前轮次请求、审批、其他工具和历史证据不足的情况仍阻止续跑，`check` 会显示排除数量。任务还在运行时可以提前接管，等待后续是否出现额度耗尽。

## 开启和停止

原任务内的真实发送已验证，但自然额度重置后的自动恢复尚未验证。建议先用 `doctor` / `check`，确认接受实验风险后，仅选择一个任务受控试用：

```sh
python3 -m codex_resume start 你的任务UUID
python3 -m codex_resume status
python3 -m codex_resume stop 你的任务UUID
```

`start` 在后台运行，可以关闭这个终端。默认同一任务累计最多尝试 3 次自动续跑；明确需要更多时使用 `--max-resumes 5`。次数按持久记录累计，重新启动不会清空去重记录或次数。

`stop` 取消后续自动发送，不撤回已发送消息，也不打断正在执行的 App 任务。监控空闲等待时约 1 秒内响应停止；已进入接口调用时会先等待其有界超时，无法撤销已经被 App 接受的消息。停止 App 中正在运行的工作仍使用 App 的停止操作。

如果账户返回多个额度桶，工具要求显式指定 `start ... --limit-id 桶ID`；不会猜测模型该使用哪个桶。

## 恢复规则

1. 每约 30 秒只读检查所选任务。暂时断连、超时或 App 退出时保留托管并等待；不会因为三次暂时断连就取消。App 可连接但没有加载这个对话时，重新核验历史资格后通过 App 的原对话链接尝试加载（最多每五分钟一次）。不预填提示词、不新建任务、不抢占所有权；发送前必须取得新的实时快照。
2. 只有最后一轮明确因额度耗尽失败才进入等待；正常结束、被中断、其他错误、审批、用户输入、暂停的目标均不自动续跑。
3. 根据服务返回的重置时间等待。五小时和周窗口均耗尽时等待更晚的时间；到时重新查询，不把“时钟已到”当成额度可用。
4. 发送前再次读取任务，核对最后一轮、模型、权限、工作目录和目标等。继承 App 设置，不提交任何审批决定。
5. 先保存发送意图，再发送一次续跑消息。App 确认新轮次后记录轮次 ID；结果不确定则停止，不自动重试。

自动发送的文字为：

> 额度恢复后，请继续本会话原有的未完成工作。先核对当前进度与工作区，不要重复已完成步骤，不扩大范围，不绕过审批。若工作已经完成或需要用户决定，请明确说明并停止。

## 需要知道的限制

- **没有稳定公开的 App 续跑接口**：内部协议采用当前版本的任务所有者发现、状态订阅和 follower-start-turn；不修改 App 文件、不注入 UI JavaScript、不修改其数据库。
- App 需要运行。失联时保留托管，等待它恢复，不另起 CLI 会话。自动加载会切换 App 的可见对话；检查操作本身不会导航。系统链接请求不等于加载成功，只有新快照才确认连接；无法加载时保持等待且不发送。不兼容协议、权限或连续非暂时性读取异常仍会停止。
- 电脑关机时不能运行；睡眠期间不会执行，唤醒后重新核验。重启电脑或进程退出后不自动重启监控，需手动 `start`。
- 内部接口没有原子的“比较旧轮次并开始新轮次”操作。发送前复查和单进程锁降低冲突，但**无法消除与用户同时操作 App 的瞬时竞态**。首版试用时请勿同时向所选任务发送消息或安排 App 自带排队消息/其他自动化；需要操作时先关闭监控。
- 快照不保证包含所有 App 排队消息。工具不会声称已全面检查队列；它不读取或改写 App 的私有排队数据库。
- 不保证任务一定完成。正常结束仅说明该轮结束，不能证明用户整个目标已达成；业务验证仍由原任务执行。
- 未确认发送记录会阻止重新接管。先在 App 人工确认发生了什么；首版不提供自动清除防重记录的命令。

## 数据与权限

只在 `~/.codex-auto-resume/` 保存任务 UUID、错误轮次 ID、发送标识、状态摘要、设置/内容指纹、进程锁及简短日志。目录仅当前用户可访问；不保存完整会话、源码、账号令牌或原始查询错误。

额度查询使用 App 附带的 `codex app-server --stdio` 和现有登录，仅允许 `account/rateLimits/read` / `thread/list` / `thread/read`；历史只读发生在明确选择后，不使用官方连接加载或续跑业务线程。该官方进程可能维护自己的正常本地运行日志。

可在子命令前指定 `--app /路径/ChatGPT.app`、`--home /路径/.codex`、`--state-dir /私有状态目录`。首次运行若受终端沙箱限制，需用户允许本地进程/socket 访问；工具不会自动放宽权限。

## 开发验证

```sh
python3 -m unittest discover -s tests -v
python3 -m compileall -q codex_resume
node --test tests/test_ui.cjs
node --check codex_resume/static/app.js
```

测试使用内存消息、回环 HTTP/HTTPS 服务和独立临时数据库，不访问账户、不修改 App、不启动真实任务。HTTPS 测试使用 OpenSSL 生成临时证书并显式信任该证书，不安装系统信任。源码仅包含自写适配代码，不包含 App 打包源码或账户数据。

界面回归可运行 `python3 tests/web_fixture.py`，打开 `http://127.0.0.1:8876/` 并输入凭据 `ui-test-only`。这只提供明确标注的模拟数据，与真实账户、状态数据库和 App 完全隔离，不能用它证明真实续跑成功。

前端回归使用 Node 自带测试工具，不需要 npm 依赖；运行产品本身仍只需要 Python。任务选择器按标题选择并标明当前选中，UUID由工具内部关联，不在列表、选中摘要或监控卡片展示。仅在默认折叠的“使用会话编号（高级）”中保留手动输入入口。切换任务或关闭窗口后，旧检查响应不会覆盖新选择。
